# 企业业绩管理表格规则解析与自动化脚本生成 Agent

这个项目用于把企业在飞书、钉钉等办公协作平台中的业绩管理表格体系，转化为可沉淀、可复用、可运行的自动化脚本项目。

推荐把这个 GitHub 项目交给 WorkBuddy、Codex 或其他 Agent 软件处理。用户只需要提供企业代号、平台、业绩管理文件夹链接和目标范围，Agent 会协助完成权限打通、文件夹读取、表格规则理解、规则文档整理和自动化脚本生成。

## 这个项目做什么

核心流程是：

```text
读取企业业绩管理文件夹
-> 识别文件夹中的表格
-> 理解表格结构、公式、依赖关系和维护规则
-> 整理企业专属规则文档
-> 生成企业专属自动化脚本
-> 后续由人员运行脚本，对表格进行复制、生成和维护
```

这个仓库本身不把能力限定在某几张固定表格上。具体支持哪些报表、每张表怎么复制、哪些单元格要清空、公式如何引用，应该由 Agent 在读取企业实际文件夹后生成到该企业的规则文档和脚本中。

## 适合的使用场景

- 企业已有一套业绩管理、经营计划、销售计划、资源分配或个人计划类表格。
- 表格在飞书、钉钉等协作平台中维护。
- 每月、每周或每个周期都需要复制上期表格并做固定修改。
- 希望把“人工复制和改表”的经验沉淀为规则文档和自动化脚本。
- 希望后续不同企业可以基于同一套流程快速生成专属项目。

## 给 Agent 的标准提示词

把 GitHub 链接发给 Agent 后，可以直接补充以下信息：

```text
请基于这个 GitHub 项目，为以下企业生成专属业绩管理自动化脚本项目。

企业代号：
平台：飞书 / 钉钉
业绩管理文件夹链接：
目标范围：

请先检查本机是否具备对应平台 CLI 能力。
如果没有登录或没有权限，请自动打开登录授权页面或文件夹权限申请页面，并提示我完成人工授权。
权限完成后，请继续读取文件夹中的表格，理解表格结构、公式、依赖关系和维护规则，整理规则文档，并生成对应自动化脚本。
```

示例：

```text
企业代号：company-xxx
平台：钉钉
业绩管理文件夹链接：https://alidocs.dingtalk.com/...
目标范围：请读取文件夹中的业绩管理表格，整理规则文档，并生成可运行的自动化脚本项目。
```

## Agent 应执行的工作

Agent 拿到企业信息后，应按以下顺序推进：

1. 识别平台：飞书、钉钉或其他协作平台。
2. 检查本机是否具备对应平台 CLI 或可调用能力。
3. 检查是否已完成平台登录授权。
4. 如果未登录，启动登录流程并打开授权页面。
5. 如果无文件夹访问权限，打开原文件夹链接，让用户在页面中申请权限。
6. 如果组织不匹配，提示用户切换组织或重新授权。
7. 如果企业级 CLI 权限未开放，提示联系管理员加入授权范围。
8. 权限通过后，读取业绩管理文件夹。
9. 识别文件夹中的表格、文档、Excel 文件和在线表格类型。
10. 读取目标表格结构、sheet 命名、公式、样式、依赖关系和人工填写区域。
11. 形成企业专属规则文档。
12. 生成企业专属自动化脚本项目。
13. 运行一次脚本或做最小验证，确认脚本可以按规则执行。

## 权限处理说明

这个项目的目标不是绕过企业权限，而是让权限处理更顺：

```text
未登录平台
-> Agent 启动对应平台登录命令，并打开授权页面。

没有文件夹访问权限
-> Agent 打开原文件夹链接，用户在页面点击申请权限。

当前账号组织不匹配
-> Agent 提示当前组织和目标文件夹所属组织，并要求切换或重新授权。

企业级 CLI 授权未开放
-> Agent 提示联系企业管理员，将当前账号加入 CLI / DWS / lark-cli 等授权范围。

权限通过后
-> 用户回复“已授权，请继续”，Agent 从失败步骤继续执行。
```

权限动作中需要人确认或管理员审批的部分，仍然由用户或管理员完成；Agent 负责发现问题、打开正确入口、说明下一步并继续后续流程。

## 输出结果

完成一次企业项目生成后，通常会得到：

```text
企业专属规则文档
企业专属配置文件
企业专属自动化脚本
运行入口脚本
必要的环境检查和授权检查逻辑
```

后续企业人员不需要重新理解全部表格规则，只需要运行生成出来的脚本，并按提示选择月份、周期或目标报表即可。

## 建议的项目结构

生成企业专属项目时，建议使用类似结构：

```text
company-xxx-performance-tool/
  README.md
  config/
    config.example.json
  rules/
    rules.md
  scripts/
    main.py
    platform_adapter.py
  run.bat
  setup_check.bat
```

其中：

- `rules/` 保存该企业的表格规则和依赖关系。
- `scripts/` 保存可执行的自动化脚本。
- `config/` 保存本机配置模板，不提交真实 token 或私有链接。
- `run.bat` 作为日常运行入口。

## 安全说明

- 不要提交真实的 `config/config.json`。
- 不要把 access token、refresh token、app secret、个人账号凭证放进 GitHub。
- 企业真实表格链接、授权信息和运行配置应保存在使用者本机。
- 如果规则文档包含企业敏感经营信息，应放在企业私有仓库或本地项目中。

## 当前边界

- 本仓库提供的是 Agent 执行框架和案例说明，不保证未读取企业表格前就能直接生成所有企业的脚本。
- 不同企业的表格结构、命名方式、公式规则和权限策略不同，必须先读取材料并整理规则。
- 飞书、钉钉等平台的企业级授权需要企业管理员允许，Agent 不能绕过管理员审批。
- 如果平台 CLI 暂不支持某些操作，Agent 应提示人工处理或改用导出 Excel 的方式分析。

# 案例：company-xl 飞书业绩管理项目

以下内容是某一家企业 XL 的实际落地案例。它不是本框架的固定能力边界，而是展示一套企业业绩管理表格如何被整理成规则文档和自动化脚本。

## 案例背景

company-xl 的业绩管理体系原本在飞书表格中维护。每个月需要围绕经营方针、事业年月计划、资源分配计划和个人计划进行复制、引用、清空和公式调整。

通过本项目，Agent 将这些人工维护动作整理为规则，并生成了可运行的飞书表格自动化脚本。日常使用时，人员可以双击入口，按提示选择月份和表格类型，脚本会完成表格复制、公式写入、依赖检查和部分人工填写区清空。

## 案例实现范围

company-xl 案例中，脚本覆盖过以下类型的表格维护：

- 经营方针修正
- 事业年月计划
- 事业资源分配计划
- 营销资源分配计划
- 研发资源分配计划
- 个人月周推移计划
- 个人周日推移计划
- 按月份统一生成一组核心表格
- 执行前依赖检查

这些名称和规则只属于 company-xl 案例。新企业不需要沿用这些表格名称，Agent 应根据新企业文件夹中的实际表格重新理解和生成规则。

## 案例中的日常使用方式

company-xl 项目生成后，使用者可以运行：

```text
run.bat
```

主菜单曾设计为：

```text
1. 统一生成X月所有表格
2. 生成单个表格
3. 检查环境和飞书授权
0. 退出
```

首次生成某类表格时，工具会要求粘贴对应飞书表格链接，并保存到本机配置。后续同一台电脑再次生成时，会优先读取本机配置。

## 案例中的权限方式

company-xl 使用飞书 `lark-cli` 操作表格。Agent 会检查：

```bash
lark-cli --version
lark-cli auth status --json --verify
```

需要授权时，引导执行：

```bash
lark-cli auth login --domain docs --domain drive
```

授权完成后，脚本才能读取、复制和修改飞书表格。

## 案例中的依赖检查

company-xl 的脚本不会直接盲目生成表格。执行前会检查：

- 上游月份表格是否存在。
- 源 sheet 是否存在。
- 被引用的上游表格是否已经生成。
- 本机是否保存过必要的表格链接。
- 授权是否可用。

如果缺少依赖，脚本会先列出缺失项并停止，避免执行到一半才报错。

## 案例中的规则沉淀

company-xl 的具体表格规则包括：

- 从上月 sheet 复制出本月 sheet。
- 根据目标月份更新标题或月份单元格。
- 按业务依赖写入跨表引用公式。
- 清空需要人工填写的原因分析、对策或计划区域。
- 按月份范围更新完成率统计公式。
- 对指定月份范围设置背景色。
- 按顺序生成上游表，再生成下游表。

这些规则的价值不在于它们适用于所有企业，而在于说明：只要 Agent 能读取企业表格并理解维护逻辑，就可以把类似的人工规则沉淀为自动化脚本。

## 如何复用这个案例

新企业不应直接照搬 company-xl 的单元格位置和表格名称，而应复用它的生成方法：

```text
提供企业文件夹链接
-> Agent 读取实际表格
-> Agent 整理该企业规则
-> Agent 生成该企业专属脚本
-> 企业人员运行脚本维护表格
```

company-xl 只是一个参考样板，用来说明最终产物会是什么样。
